01

Give your Mac access

Use your private invitation to add this Mac to lab. The same steps work for your own new server or a server a friend has shared with you. You don’t need root access. Everyone using lab shares its apps and files.

Open your private invitation link to enable access.

Have an invitation code instead?
Find or create your Mac’s SSH key

Open Terminal on your Mac. If you already have a key, copy its public part:

pbcopy < ~/.ssh/id_ed25519.pub

Run that command in Terminal: it silently copies your public key to the clipboard. Return here and press ⌘V in the public-key field. Nothing is printed in Terminal.

If that file does not exist, create a dedicated key with the command below. Choose a passphrase when prompted. If asked to overwrite an existing file, answer no.

ssh-keygen -t ed25519 -f ~/.ssh/lab_ed25519 -C "my-lab"

Then copy it:

pbcopy < ~/.ssh/lab_ed25519.pub

For an existing key with a different filename, use its matching .pub file.

Paste your public .pub file only. Clicking Enable access sends it securely to this server and authorizes it for lab. Your private key stays on your Mac.

Your Mac is authorized

You can now connect as lab. Continue with the connection test below, then open Claude Desktop.

No invitation yet?

Ask the server owner or their setup agent for a private invitation. If you’ve just installed your own server, your setup agent should give you this link at handoff. Once you can connect as lab, ask your agent to run lab-access invite to invite another laptop or friend. Keep invitation links private; they expire after 24 hours.

Already connected before?

If this Mac’s key is already authorized, skip to step 2. You don’t need another invitation to keep using it. For a new laptop, request a new invitation.

02

Check your connection

Use ~/.ssh/lab_ed25519 if you created the key above. This is a file path, not the key’s contents. Do not include .pub.

Run this in your Mac’s Terminal. Success prints lab and /srv/lab. A key passphrase prompt unlocks your Mac’s key. A lab account password prompt means key login still needs fixing; lab has no default password.
Connection trouble?
Check that you pasted the public key matching the private-key path above, saw “Your Mac is authorized” after enabling access, and used the same server address. Root access alone does not authorize lab. For a new host, verify its fingerprint with your server administrator or provider console before accepting it.
