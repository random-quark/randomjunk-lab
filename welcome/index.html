01

Give your Mac access

This is a one-time step. Root was used to install the server; lab is the account you’ll use to build things. Each account needs its own key authorization.

Find or create your Mac’s SSH key

Open Terminal on your Mac. If you already have a key, copy its public part:

pbcopy < ~/.ssh/id_ed25519.pub

If that file does not exist, create a dedicated key with the command below. Choose a passphrase when prompted. If asked to overwrite an existing file, answer no.

ssh-keygen -t ed25519 -f ~/.ssh/lab_ed25519 -C "my-lab"

Then copy it:

pbcopy < ~/.ssh/lab_ed25519.pub

For an existing key with a different filename, use its matching .pub file.

Paste the public .pub file only. This field stays in this browser tab; it is not uploaded or saved. Your private key stays on your Mac.

Authorize it using your administrator access

Copy this command into Terminal on your Mac. It connects as root and adds only this public key to lab, preserving existing keys. Use your root SSH key or server root password if prompted.

Preparing or copying the command does not change the server. Run it and wait for “Public key authorized for lab”. If someone else administers your server, give them your public key to authorize instead.


Already authorized through the private setup form?
Skip adding it again once your administrator has applied it. Saving the key in that form alone does not activate access. Continue with the connection test below.


02
Check your connection
Use ~/.ssh/lab_ed25519 if you created the key above. This is a file path, not the key’s contents. Do not include .pub.
Run this in your Mac’s Terminal. Success prints lab and /srv/lab. A key passphrase prompt unlocks your Mac’s key. A lab account password prompt means key login still needs fixing; lab has no default password.
Connection trouble?
Check that you pasted the public key matching the private-key path above, ran the access command successfully, and used the same server address. Root access alone does not authorize lab. For a new host, verify its fingerprint with your server administrator or provider console before accepting it.
